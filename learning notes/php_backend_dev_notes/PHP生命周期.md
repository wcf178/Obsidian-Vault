PHP 的生命周期是指一个 PHP 脚本从启动到结束所经历的完整过程。理解这一机制是深入掌握 PHP 内核、进行性能优化和排查问题的基础。

PHP 的核心设计遵循着清晰的“启动-处理-关闭”闭环，其完整的生命周期通常分为以下五个核心阶段：

1. 模块初始化阶段（MINIT）
* 触发时机：在 PHP 进程启动时执行，整个进程生命周期内仅执行一次。
* 主要操作：加载并初始化所有 PHP 扩展（如 MySQL、PDO 等），注册内置常量、全局函数和类，申请全局资源，以及初始化 Zend 引擎和 PHP 内核。

2. 请求初始化阶段（RINIT）
* 触发时机：每次 HTTP 请求或 CLI 命令到来时都会执行。
* 主要操作：初始化请求级别的全局变量（如 _GET、_POST、$_SERVER 等超全局变量），重置执行环境，清空上一次请求的变量，并启动输出缓存机制。

3. PHP 脚本执行阶段
* 触发时机：请求初始化完成后立即开始。
* 主要操作：Zend 引擎对 PHP 文件进行解析和处理，具体流程为：词法分析（生成 Tokens） → 语法分析（生成抽象语法树 AST） → 编译为中间字节码（Opcode） → 最终由虚拟机执行 Opcode 以处理业务逻辑并输出响应内容。

4. 请求关闭阶段（RSHUTDOWN）
* 触发时机：当前请求处理完成后执行。
* 主要操作：销毁本次请求产生的所有变量和资源，将输出缓冲区的内容 flush 发送，依次调用通过 register_shutdown_function() 注册的钩子函数，以及触发对象的析构函数（__destruct()）。

5. 模块关闭阶段（MSHUTDOWN）
* 触发时机：PHP 进程退出前触发。
* 主要操作：释放持久化资源，关闭持久连接，卸载所有的扩展模块并清理核心状态。

💡 不同运行模式下的生命周期差异

PHP 的运行模式主要分为 CLI（命令行）和 FPM（Web 进程管理器），两者的生命周期存在显著差异：

* CLI 模式：适用于定时任务、数据导入导出等单次脚本执行场景。每次执行都会启动一个独立的 PHP 进程，走完完整的五步生命周期（MINIT → RINIT → 执行 → RSHUTDOWN → MSHUTDOWN），执行完毕后进程即被销毁。
* FPM 模式：专为 Web 应用设计的主流模式。Worker 进程常驻内存，仅在启动时执行一次 MINIT；之后每接收到一个 HTTP 请求，仅循环执行 RINIT → 执行 → RSHUTDOWN 这三个步骤，进程不会销毁，从而避免了重复初始化的开销，效率更高。
