CGI、FastCGI 和 PHP-FPM 是 Web 服务器与后端应用程序（如 PHP）交互时涉及的三个核心概念。它们分别代表了标准协议、协议的优化版本以及具体的进程管理工具。

1. CGI (Common Gateway Interface，公共网关接口)
* 定义：CGI 是一种标准协议，用于 HTTP 服务器与外部程序之间的通信。它使得服务器可以动态生成网页内容，实现表单提交、数据库交互等交互功能。
* 工作原理：每当 Web 服务器接收到一个需要通过 CGI 处理的请求时，它会创建一个新的子进程来执行对应的 CGI 脚本。请求数据通过环境变量和标准输入输出传递，处理完成后结果返回给服务器，随后该进程被销毁。
* 痛点：这种“每请求一进程”的模型存在严重的性能瓶颈。频繁地创建和销毁进程会带来巨大的系统开销，且每个进程都需要重新初始化解释器、建立数据库连接等资源，无法复用，导致高并发下响应极慢。

2. FastCGI (快速公共网关接口)
* 定义：FastCGI 是对传统 CGI 的改进协议，旨在解决 CGI 的性能瓶颈问题。
* 核心改进：FastCGI 的核心思想是常驻内存。它在启动时预先创建一组 Worker 进程（进程池），这些进程不会在处理完单个请求后销毁，而是持续存活以处理后续请求。
* 工作机制：Web 服务器与 FastCGI 进程之间通过 Socket（Unix Socket 或 TCP）进行通信。当请求到来时，Web 服务器将请求转发给空闲的 Worker 进程，处理完毕后进程归还到进程池等待下一个请求。这种方式避免了频繁的进程创建/销毁开销，并支持数据库连接等资源的复用，大幅提升了并发处理能力。

3. PHP-FPM (PHP FastCGI Process Manager)
* 定义：PHP-FPM 并不是一个 Web 服务器，而是一个专门用于管理 PHP FastCGI 进程的管理器。它是 FastCGI 协议在 PHP 生态中的主流实现方案。
* 核心作用：PHP-FPM 负责管理底层的 PHP-CGI Worker 进程池。它提供了高级的进程管理功能，包括进程的平滑启动/停止、动态/静态子进程的按需分配、超时控制、慢日志记录以及错误恢复机制等。
* 典型架构：在现代 Web 部署中（如 Nginx + PHP-FPM），Nginx 作为前端 Web 服务器接收 HTTP 请求，遇到 .php 请求时，通过 fastcgi_pass 指令将请求按 FastCGI 协议转发给 PHP-FPM；PHP-FPM 分配一个 Worker 进程执行 PHP 脚本，并将生成的 HTML 响应回传给 Nginx，最终返回给客户端。

💡 三者的关系总结
简单来说：CGI 是最初定义的“通信规则”，但效率低下；FastCGI 是升级版的“高效通信规则”，引入了进程池复用的概念；而 PHP-FPM 则是 PHP 语言为了落地这套高效规则而开发出的具体“大管家（进程管理器）”。
