zval（Zend Value）是 PHP 中最核心的底层数据结构。由于 PHP 是一种动态弱类型语言，变量的类型可以在运行时随时改变，因此 Zend 引擎使用 zval 这个统一的 C 语言结构体来封装和表示所有的 PHP 变量（如整数、字符串、数组、对象等）。

从 PHP 7 开始，zval 的结构经历了重大的重构与优化，变得更加紧凑高效。其核心主要由以下几个部分组成：

1. zval 的核心组成
一个标准的 zval 结构体通常包含以下关键部分：
* value（值）：这是一个联合体（union），用于存储变量的实际数据。对于小于 64 位的简单类型（如整型、浮点型），值直接存储在联合体中；而对于复杂类型（如字符串、数组、对象），这里存储的是指向对应内存结构的指针。
* type（类型标识）：用于记录当前变量所属的数据类型（例如 IS_LONG、IS_STRING、IS_ARRAY 等）。无论变量是什么类型，虚拟机都会先读取 type 字段，再按类型去 value 中提取数据，这极大简化了虚拟机的逻辑。
* u2（附加信息）：一个联合体，用于存储特定类型的附加元信息，例如哈希表冲突链的下一个节点指针、AST 节点的代码行号等。

2. 内存管理与引用计数
在 PHP 5 时代，zval 内部还包含 refcount__gc（引用计数）和 is_ref__gc（是否为引用）字段。但从 PHP 7 开始，为了极致压缩内存，这两个字段被移出或重构，引用计数更多地由容器（如数组、字符串本身）来管理。

这种机制支撑了 PHP 极其重要的两个内存特性：
* 写时复制（Copy-on-Write, COW）：当执行 b = a; 这样的普通赋值时，PHP 并不会立刻复制一份数据，而是让两个变量共享同一个底层的 zval，并将引用计数加 1。只有当其中一个变量被修改时，才会触发“分离（separation）”，真正复制出一个新的副本。
* 垃圾回收（GC）：通过追踪引用计数，PHP 能够自动判断何时可以释放不再使用的内存。针对复杂的循环引用问题，PHP 引入了同步周期性垃圾回收器进行深度清理。

3. PHP 7/8 的体积优化
早期的 PHP 版本中，zval 往往需要单独分配内存且体积较大。而在 PHP 7 及以后的版本中，zval 被重构为栈内联值（Value Semantics），在 64 位系统下大小被严格缩减至 16 字节。这一设计使得 PHP 在处理高并发请求、创建成千上万个变量时，内存开销依然能保持在极低的水平。

总结来说，zval 就像是 PHP 内核中的一个“智能快递盒”，它用统一的规格装载各种类型的数据，配合引用计数机制，完美地平衡了动态语言的灵活性与底层运行的高性能。
