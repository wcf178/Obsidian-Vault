PHP 的运行流程与生命周期紧密相关，其核心是由 Zend 引擎驱动的。无论是哪种运行模式（如 FPM 或 CLI），当 PHP 接收到请求并进入脚本执行阶段时，Zend 引擎都会严格按照以下四个步骤来处理代码：

1. 词法分析 (Lexing)
词法分析器会逐个字符地扫描 PHP 源代码，识别出关键字、变量、常量、操作符等元素，并将它们转换为一个个独立的“令牌”（Tokens）。这些令牌流将作为后续语法分析的输入。

2. 语法分析 (Parsing)
语法分析器接收词法分析生成的令牌流，并根据 PHP 的语法规则验证其正确性。随后，它会将这些令牌构建为一棵抽象语法树（AST）。AST 能够清晰地反映代码的逻辑关系和层级结构，为后续的编译提供基础。

3. 编译 (Compilation)
在这一阶段，编译器会将 AST 转换为 Zend 虚拟机能够理解的中间字节码（Opcode）。Opcode 类似于 CPU 的机器码（例如 ZEND_ADD 表示加法，ZEND_ASSIGN 表示赋值）。同时，系统还会对 Opcode 序列进行优化，生成最终可执行的 Opcode 数组。

4. 执行 (Execution)
Zend 虚拟机按顺序读取并执行 Opcode 数组中的指令。在执行过程中，虚拟机会维护调用栈和变量符号表，处理函数调用和控制流，从而完成实际的业务逻辑运算，并最终输出响应内容。

💡 性能优化补充：
在默认情况下，上述四个步骤在每个请求到来时都会重复执行。但在现代 PHP 生产环境中，通常会开启 OPcache 扩展。OPcache 会将编译后的 Opcode 缓存到共享内存中，这样在后续请求中就可以直接跳过词法分析、语法分析和编译阶段，直接进入执行阶段，从而大幅提升运行效率。
