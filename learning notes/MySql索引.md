
1. 为什么要使用B+树，而不是使用二叉树、红黑树、HASH索引？
	二叉树在递增索引的表现上表现为一个链表
	红黑树的树高在索引数量大的时候 高度很大，需要做很多次I/O操作
	HASH索引查找的速度非常快，但是不支持范围查询（范围查询走不了索引），除此之外还有哈希冲突的问题。
	B树没有无法支持范围查询、索引是放在所有节点上的，单个节点能够存储的索引数量少，同等数据量下 树的高度更高，查询所需的I/O操作就更多。
	
2. 什么是B+树？
	 B+ 树是一种多路平衡查找树，非叶子节点只存冗余索引键和子节点指针，不存数据行，所有数据都在叶子节点，叶子节点按 key 有序，并用双向链表连接。
	 
3. 为什么使用B+树而不是用B树？
	 B树的叶子节点没有双向指针，执行范围查询的
	 其次，B树的每个索引节点放了data数据，树中每个节点的能存储的索引更少，导致在同等数据量的情况下B树的高度更高，在执行查询的时候，所需要的磁盘读取次数和对比次数更多，也更耗时。
	 
4. 什么是MyISAM存储引擎，查找过程是什么样的？
	 MyISAM 是 MySQL 的一种非事务存储引擎：不支持事务、行级锁和外键，锁粒度是表级锁；索引和数据分开存，`.MYI` 存索引，`.MYD` 存数据，索引是 B+ 树，且是非聚簇索引，叶子节点存的是数据行在 `.MYD` 中的地址。
	 查找过程：
	1. SQL 解析、优化后，如果选择走索引，就在 `.MYI` 的 B+ 树中查找目标键。
	2. 找到叶子节点后，拿到对应数据行的物理地址。
	3. 再回表到 `.MYD` 中按地址读取整行数据。
	4. 如果是覆盖索引，只读索引即可返回；如果没有合适索引，则直接全表扫描 `.MYD`。

5. 什么是Innodb存储引擎，和MyISAM的区别是什么？
	 InnoDB 是 MySQL 默认的事务型存储引擎，核心特点：支持事务 ACID、行级锁、外键、MVCC 和崩溃恢复；采用聚簇索引，主键索引叶子节点直接存整行数据，二级索引叶子存主键值，通常需要回表。
	 查找过程：
	 - 走主键：在聚簇索引 B+ 树定位，叶子直接取整行。
	 - 走二级索引：先找到主键，再回主键索引取整行。
	 - 覆盖索引：所需列都在索引里，直接返回。
6. 什么是聚集索引？
	聚集索引是叶子节点包含了完整的数据记录，Innodb使用的就是聚集索引。
	
7. 什么是非聚集索引？
	索引和数据是分开的。MyISAM使用的就是非聚集索引。索引放在MYI文件，数据放在MYD文件，每次查找索引之后都需要回表查找完整的行数据。
	
8. Innodb的主键索引是聚集索引，非主键索引使用使用的是非聚集索引。
	非主键索引的叶子节点存储的是主键值。根据非聚集索引查找到主键值之后，再去查主键索引（回表）
	
9. 为什么Innodb的表要建立主键？并且推荐使用int类型的自增主键？
	不建的话，数据库也会创建一列 row_id,  然后创建聚集索引。自己设定主键的化还能用，数据库自己生成的是隐藏的不能自己拿来用。
	相对于uuid类型的主键来说整型主键节省存储空间、在索引查找中int类型的对比更快，
	为什么要自增？新增数据索引永远会在叶子阶段后面插。没有自增的话，可能会导致叶子节点分裂重新构建树，从而导致插入性能降低。
	
10. 联合索引的底层存储结构是什么样的？
	 联合索引的排序是按照联合索引的顺序进行排序的。如果说联合索引中的第一个列就可以进行对比，则就按照第一列进行排序，如果说第一个列的值都一样，才使用第二列进行对比。
	
11. 什么是最左前缀原则？
	 最左前缀原则：对联合索引 `(a, b, c)`，查询必须从最左列 `a` 开始，且不能跳过中间列，才能利用索引定位。
	 所以没有最左列 `a`，B+ 树就无法二分查找，只能全表扫描或全索引扫描，效率很低。MySQL 优化器遵循这个规则，是为了保证索引真正能减少扫描范围、快速定位数据。
