# RabbitMQ 学习笔记

## 1. 死信队列（DLQ）

当消息满足以下任一条件时，消息会被投递到死信交换机，最终进入死信队列：

- 消息被消费者拒绝（`reject` / `nack`），且不重新入队。
- 消息过期（TTL 到期）。
- 队列达到最大长度，旧消息被移出。

> [!note] 配置要求
> 需要在业务队列中配置死信交换机（Dead Letter Exchange）和死信路由键（Dead Letter Routing Key）。

## 2. 可靠发送与可靠消费

### 2.1 生产者：可靠发送

1. **开启 Publisher Confirm**
   - 生产者开启 `publishConfirm`。
   - 建立冗余的消息发送记录表。
   - 对收到发送成功确认的消息，更新其发送状态。

2. **开启 `mandatory`**
   - 用于处理消息已进入交换机，但无法路由到队列，或因其他原因无法入队的情况。
   - 通过 `ReturnCallback` 接收无法路由的消息，并将消息落库，便于后续排查和补偿。

### 2.2 Broker：RabbitMQ Server

开启以下持久化配置：

- 消息持久化
- 队列持久化
- 交换机持久化

### 2.3 消费者：可靠消费

1. **手动确认消息**
   - 关闭自动 ACK。
   - 业务处理完成后再手动 ACK。
   - 处理失败时，根据业务情况决定是否重新入队。

2. **限制重试次数**
   - 设置最大重试次数。
   - 达到上限后，将消息转入死信队列。
   - 对死信消息进行人工排查和重放。

3. **保证幂等性**
   - 基于业务唯一键进行去重。
   - 避免消息重复投递导致业务重复处理。

### 2.4 最终兜底方案：消息状态表 + 定时重发

1. 发送方发送消息后，将消息写入消息状态表，并标记为“未签收”。
2. 接收方处理完成后，调用发送方接口，更新对应消息的状态。
3. 定时任务扫描仍处于“未签收”状态的消息，并进行重发。

## 3. RabbitMQ 的交换机类型

| 类型 | 路由方式 | 说明 |
| --- | --- | --- |
| `direct` | 精确匹配路由键 | 发送消息时携带路由键，消息只会路由到绑定了相同路由键的队列。 |
| `fanout` | 广播 | 消息会发送到所有与该交换机绑定的队列，忽略路由键。 |
| `topic` | 通配符匹配 | 根据路由键进行模式匹配，支持 `*` 和 `#` 等通配符。 |
| `headers` | 消息头匹配 | 根据消息头属性进行路由，实际使用较少。 |

### 3.1 `direct` 交换机

根据路由键进行精确匹配：

```text
消息 routing key = order.created
队列绑定 routing key = order.created
```

只有绑定了 `order.created` 的队列可以收到该消息。

### 3.2 `fanout` 交换机

广播消息到所有绑定队列，不匹配路由键。

### 3.3 `topic` 交换机

根据路由键模式进行匹配：

- `*`：匹配一个单词。
- `#`：匹配零个或多个单词。

例如，绑定键 `order.*` 可以匹配 `order.created`，但不能匹配 `order.created.success`。

### 3.4 `headers` 交换机

根据消息头中的属性进行匹配，使用场景较少。
