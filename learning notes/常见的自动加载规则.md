# 常见的自动加载规则

Composer 常见的自动加载方式主要有 `PSR-4`、`classmap` 和 `files`。

| 规则 | 适用场景 | 加载方式 |
| --- | --- | --- |
| `PSR-4` | 按命名空间组织的类 | 将命名空间映射到目录，按类名推导文件路径。 |
| `classmap` | 目录结构不符合 PSR 规范的类 | 扫描指定目录，生成“类名 → 文件”的映射。 |
| `files` | 全局函数和常量 | 在 Composer 自动加载文件时直接引入指定文件。 |

## 1. PSR-4

`PSR-4` 是最常用的自动加载规则，核心是将命名空间前缀映射到目录。

### 配置示例

```json
{
  "autoload": {
    "psr-4": {
      "App\\": "src/"
    }
  }
}
```

配置后，类名：

```php
App\Controller\HomeController
```

会映射到文件：

```text
src/Controller/HomeController.php
```

映射规则：

1. 去掉命名空间前缀 `App\`。
2. 将剩余命名空间转换为目录层级。
3. 将类名转换为文件名，并补上 `.php` 扩展名。

## 2. `classmap`

`classmap` 会扫描指定目录，生成静态的“类名 → 文件路径”映射。

### 配置示例

```json
{
  "autoload": {
    "classmap": [
      "database/seeds"
    ]
  }
}
```

适用场景：

- 目录结构不符合 PSR-4 规范。
- 类文件命名或存放位置不便于通过命名空间推导。
- 需要兼容旧项目或第三方代码。

> [!note] 原理
> Composer 会扫描配置的目录，识别其中的类，并生成类名到文件路径的静态映射。运行时不需要再次遍历目录。

## 3. `files`

`files` 用于直接加载指定文件，常用于全局函数和常量。

```json
{
  "autoload": {
    "files": [
      "src/helpers.php"
    ]
  }
}
```

### 为什么需要 `files`？

PHP 的自动加载机制主要针对以下类型：

- 类（class）
- 接口（interface）
- Trait

它不会因为调用全局函数而自动加载对应文件。因此，全局函数和常量文件需要通过 `files` 显式加载。

例如，`src/helpers.php` 中可以定义全局辅助函数：

```php
<?php

function format_money(float $amount): string
{
    return number_format($amount, 2);
}
```

## 4. 三种规则的选择

- **优先使用 `PSR-4`**：适合规范组织的新代码和业务类。
- **使用 `classmap`**：适合无法按 PSR-4 组织的旧代码或特殊目录。
- **使用 `files`**：适合全局函数、常量等非类代码。
